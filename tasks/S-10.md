## Ziel
`board-done.yml` setzt nach dem Merge eines PR das Ticket auf done. Der Lauf scheitert dreimal in Folge (PR #29, D-05, S-07) schon im Schritt `actions/checkout@v4` mit „could not read Username for 'https://github.com': terminal prompts disabled“. Die Tickets wurden von Hand auf done gesetzt. Ursache beheben.

## Fertig, wenn …
- Nach dem Merge eines Test-PR setzt der Workflow das Ticket ohne Handarbeit auf done (needs_hw bleibt needs_hw)
- `python tools/board.py validate` grün

## Kontext
Läufe 41406373840 (D-08), 41404146570 (D-05), 41404035115 (S-07). Verdacht: das Board-Token (ADR-013) fehlt, ist abgelaufen oder hat nach dem Umzug des Repos nach Frostbyte-robotics-vec keine Rechte. Das kann nur ein Mensch mit Zugriff auf die Repo-Einstellungen prüfen. Regeln: CLAUDE.md.

## Übergabe
Blockiert, nur ein Repo-Admin kann es lösen. Befund: Secret BOARD_TOKEN existiert (gesetzt 2026-11-01), der Checkout scheitert trotzdem. Wahrscheinlichste Ursache: der fine-grained PAT gehört dem Konto matelechner01 und gilt nur für das alte Repo matelechner01/frostbyte; das Repo ist nach Frostbyte-robotics-vec/frostbyte umgezogen.
Lösung (Admin): 1) github.com → Settings → Developer settings → Fine-grained tokens → neuer Token, Resource owner = Organisation Frostbyte-robotics-vec (ggf. Org muss PATs erlauben/genehmigen), nur Repo frostbyte, Contents: read/write. 2) Repo Settings → Secrets and variables → Actions → BOARD_TOKEN ersetzen. 3) Admin-Ausnahme im Ruleset des neuen Repos prüfen (Token-Inhaber muss Admin/Bypass sein). 4) Test: nächster gemergter ticket/*-PR; Workflow muss grün sein. Danach status todo → erledigen, ADR-013 um „Token gehört der Organisation“ ergänzen.
Bis dahin nach jedem Merge: `python3 tools/board.py status <ID> done`, auf main committen und pushen.
